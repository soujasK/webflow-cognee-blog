Revenue Intelligence & Spoken Dialogue: Building the Gong Call Transcripts Connector for Cognee

MERGETOBER 2026 OFFICIAL ROADMAP #4743 REVENUE INTELLIGENCE COGNIFY Published: October 13, 2026 Author: Soujas K

Official Roadmap Initiative: This connector targets upstream issue topoteretes/cognee#4743, authored by maintainer @NMZivkovic. It bridges spoken customer conversations, enterprise objections, and account commitments directly into Cognee knowledge graphs.

1. Executive Summary & Problem Framing

In B2B enterprises, the most consequential commitments and unfiltered customer insights live in spoken dialogue recorded during sales discovery, technical demonstrations, and executive steering calls. While tools like Gong capture and transcribe these audio streams, this data typically remains locked within conversational intelligence dashboards, disconnected from the broader enterprise knowledge base.

Autonomous agents powering solution architecture, contract review, or account management require direct access to these customer interactions. Without a dedicated connector, developers must build bespoke export pipelines that flatten conversational structure and discard vital metadata like speaker identity and conversational direction.

The cognee-community-connector-gong package solves this by establishing a direct ingest pipeline that transforms raw Gong call logs into structured Cognee memory documents, preserving conversational context and speaker attribution throughout the graph synthesis lifecycle.

2. Gong REST API Architecture & Data Extraction

Gong's REST API v2 segregates call metadata from detailed dialogue transcripts. To construct an accurate graph memory document, our connector coordinates a two-phase data retrieval workflow:

  • Call Discovery (GET /v2/calls): Retrieves high-level session metadata, including unique call identifiers, title, direction (inbound vs. outbound), duration, and scheduled timestamp.
  • Transcript Fetch (POST /v2/calls/transcript): Accepts an array of call identifiers in a filter payload and returns timestamped monologue sequences, delineating speaker IDs and sentence arrays.

Authentication is handled using HTTP Basic authentication with a base64-encoded combination of GONG_ACCESS_KEY and GONG_SECRET_KEY, standardizing client requests across standard production environments: 

class GongClient:
    """Client for Gong REST API v2."""

    def __init__(
        self,
        access_key: str,
        secret_key: str,
        base_url: str = "https://api.gong.io",
        client: httpx.Client | None = None,
    ) -> None:
        self.access_key = access_key
        self.secret_key = secret_key
        self.base_url = base_url.rstrip("/")
        self._client = client or httpx.Client(timeout=30.0)

    def _get_headers(self) -> dict[str, str]:
        auth_str = f"{self.access_key}:{self.secret_key}"
        encoded_auth = base64.b64encode(auth_str.encode("utf-8")).decode("utf-8")
        return {
            "Authorization": f"Basic {encoded_auth}",
            "Content-Type": "application/json",
            "Accept": "application/json",
        }

3. Speaker Attribution & Dialogue Reconstruction

A common failure in naive audio transcription ingest is merging multi-party monologues into an unstructured text dump. When Cognee runs entity extraction and relationship discovery over unstructured transcripts, it needs clear boundaries between speaker statements to avoid attributing customer objections to sales engineers or vice versa.

The connector reconstructs conversational turns into a clean markdown dialogue representation. Each speaker segment is tagged with their speaker role or identifier, and key call parameters (direction, duration, timestamps) are formatted into header sections for optimal chunking: 

full_body = [
    f"# Call: {title}",
    f"**Call ID:** {call_id}",
    f"**Date:** {started}",
    f"**Duration (sec):** {duration}",
    f"**Direction:** {direction}",
    "",
    "## Transcript",
    "\n\n".join(dialogue_lines) if dialogue_lines else "No transcript available.",
]

4. DLT Pipeline & Cognee Integration Lifecycle

Following the Cognee community standard, the connector implements a dlt source exposing a calls resource. Crucially, the returned pipeline source is tagged with DOCUMENT_SOURCE_ATTR = "gong", instructing Cognee's ingestion engine to register the stream as a formal document source: 

@dlt.source(name="gong")
def _source() -> Any:
    return [calls_resource]

source = _source()
setattr(source, DOCUMENT_SOURCE_ATTR, "gong")
return source

Once added to the pipeline via await cognee.add(source), executing await cognee.cognify() converts conversational turns into knowledge graph triples:

  • Entity Nodes: Identified customers, competitors, software platforms, and engineering terms.
  • Relationship Edges: Relationships such as (Customer)-[MENTIONED_CONCERN]->(Data Sovereignty) and (Sales Rep)-[COMMITTED_DELIVERABLE]->(Q4 Roadmap).
  • Temporal Memory: Indexed call timestamps enabling chronological reasoning across sales quarters.

5. Offline Verification & Testing Rubric

The package includes a comprehensive, 100% offline unit test suite built with pytest and httpx.MockTransport. No live network calls or active Gong API credentials are required during continuous integration runs: 

def test_gong_client_get_calls(mock_calls_response):
    def mock_handler(request: httpx.Request):
        assert "Basic " in request.headers["Authorization"]
        assert "/v2/calls" in request.url.path
        return httpx.Response(200, json=mock_calls_response)

    client = httpx.Client(transport=httpx.MockTransport(mock_handler))
    gong_client = GongClient("test-key", "test-secret", client=client)
    calls = gong_client.get_calls()

    assert len(calls) == 1
    assert calls[0]["id"] == "call-901"
    assert calls[0]["title"] == "Enterprise Cloud Architecture Review"

6. Production Usage Example

Deploying the Gong connector in production requires only configuring standard environment variables and invoking Cognee's asynchronous API: 

import asyncio
import os
import cognee
from cognee_community_connector_gong import gong_source

os.environ["GONG_ACCESS_KEY"] = "gong-access-key-id"
os.environ["GONG_SECRET_KEY"] = "gong-secret-access-token"

async def main():
    # 1. Initialize connector source
    source = gong_source()

    # 2. Add raw streams to pipeline
    await cognee.add(source)

    # 3. Construct knowledge graph
    await cognee.cognify()

    # 4. Query synthesized spoken memory
    insights = await cognee.search(
        "What security requirements did enterprise prospects raise during architecture calls?"
    )
    for insight in insights:
        print(insight)

if __name__ == "__main__":
    asyncio.run(main())
