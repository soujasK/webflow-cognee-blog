Incident Memory & Real-Time On-Call: Building the Atlassian Opsgenie Connector for Cognee

MERGETOBER 2026 CONNECTOR INCIDENT MGMT COGNIFY Published: October 13, 2026 Target Issue: topoteretes/cognee#5682

In engineering organizations running Atlassian infrastructure, Opsgenie serves as the central hub for alert routing, incident escalation, and on-call engineer rotations. While monitoring dashboards display active alerts, AI developer agents and site reliability tools have historically operated blind: they lack contextual memory of active P1-P5 outages, historical incident resolutions, and active escalation paths.

To resolve this, we engineered cognee-community-connector-opsgenie. This package pulls alert telemetry and rotation schedules via the Opsgenie REST API v2, transforms them into structured markdown documents, and feeds them into Cognee's persistent memory graph.

1. The Problem: Operational Amnesia in AI Agents

When an outage strikes, engineering teams need automated agents capable of answering questions such as:

  • "Which service had a P1 latency alert within the last 4 hours?"
  • "Who is the active on-call engineer for the payment gateway rotation?"
  • "Has this database lockup alert occurred in previous sprint deployments?"

Without a persistent memory connector, querying an LLM produces either generic operational advice or hallucinated schedules. Opsgenie data must be indexed into Cognee with explicit document boundaries and entity relationships.

Architecture Principle: In Cognee, document sources declare DOCUMENT_SOURCE_ATTR = "cognee_document_source" with value "opsgenie". This routes ingested records directly into Cognee's document model rather than raw database tabular schemas.

2. Opsgenie REST API v2 Ingestion Pipeline

The connector implements a decoupled HTTP client (OpsgenieClient) targeting two distinct operational surfaces:

  • Alert Telemetry (/v2/alerts): Fetches alert ID, message, description, severity priority (P1 through P5), status, affected entities, and responder teams.
  • On-Call Rotations (/v2/schedules): Fetches defined schedules and queries active rotation participants via /v2/schedules/{id}/on-calls.

3. Knowledge Graph Topology

When Cognee processes Opsgenie documents through cognify(), the memory layer extracts nodes and directional edges reflecting real-world incident ownership:

  • (OpsgenieAlert)-[:AFFECTS]->(ServiceEntity)
  • (OpsgenieAlert)-[:ASSIGNED_TO]->(ResponderTeam)
  • (OpsgenieSchedule)-[:ACTIVE_ON_CALL]->(ResponderUser)
  • (ResponderUser)-[:MEMBER_OF]->(ResponderTeam)
