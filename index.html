Giving AI Agents a CMS Memory: The Webflow Connector

🔗 Dedicated Article Permalink: webflow.html →

Webflow powers millions of production web applications, marketing sites, and documentation repositories. When teams deploy autonomous AI agents (such as customer support assistants, technical sales copilots, or internal research bots), they usually resort to web scraping or crawler APIs.

Web crawling introduces silent failure modes: HTML navigation wrappers and cookie consent banners corrupt embedding spaces, CSS stylesheet changes trigger redundant recalculations, and unpublished or deleted articles linger in vector memory indefinitely.

Systems Topology: Webflow CMS to Graph Memory Pipeline dlt replace · DOCUMENT_SOURCE_ATTR
Stage 1 · Ingress
Webflow API v2
OAuth 2.0 / Bearer auth, paginated collection items & live CMS snapshots. Implements 429 exponential backoff.
Protocol: GET /v2/collections/{id}/items
Stage 2 · DLT Runtime
AST Transformer
Sanitizes raw HTML to Markdown AST, extracts image/code blocks, routes via DOCUMENT_SOURCE_ATTR.
Staging: DuckDB Buffer (replace)
Stage 3 · Cognify Core
Cognify NLP Engine
Bypasses tabular SQL schema. LiteLLM dense embeddings + LLM entity-relation triplet extraction.
Extractor: (CMSItem)-[:TOPIC]->(Entity)
Stage 4 · Persistence
Dual Store & RAG
Dense vector index (Qdrant/Milvus) for ANN similarity + Cypher graph topology (FalkorDB) for multi-hop recall.
Query: await cognee.search(...)
⚡ Ingress: HTTPS JSON ➔ Staging: DuckDB Memory ➔ Ingestion: DOCUMENT_SOURCE_ATTR ➔ Storage: Vector + Cypher Graph

Architectural Design

  • Document-Mode Ingestion: By attaching DOCUMENT_SOURCE_ATTR = "webflow", records bypass rigid relational schemas and route directly through Cognee's natural language entity extraction pipeline.
  • Semantic Markdown Formatting: Raw HTML rich text fields are cleanly converted to GitHub-flavored Markdown headers, lists, and code blocks while preserving canonical URLs and publication timestamps.
  • Automatic Forget-on-Delete: Utilizing write_disposition="replace", whenever an article is unpublished or deleted upstream, it falls out of the staging batch and Cognee's orphan_cleanup automatically prunes stale entities and graph edges.
import cognee
from cognee_community_connector_webflow import webflow_source

# 1. Initialize connector
source = webflow_source(token="WEBFLOW_API_TOKEN", site_id="SITE_ID")

# 2. Add to Cognee memory and cognify
await cognee.add(source)
await cognee.cognify()

# 3. Query the knowledge graph
results = await cognee.search("What pricing changes were introduced in our Q3 update?")
print(results)

Engineering Team Brains: The Slab Wiki Connector

🔗 Dedicated Article Permalink: slab.html →

Slab is the internal knowledge hub where engineering organizations publish system architecture RFCs, infrastructure runbooks, incident postmortems, and team onboarding playbooks.

Without direct integration into team wikis, AI coding assistants have zero visibility into why architectural tradeoffs were made, which microservices own specific domain logic, or how to triage database failover events.

Systems Topology: Slab GraphQL to Knowledge Graph Pipeline GraphQL v1 · Cursor Connection
Stage 1 · GraphQL Ingress
Slab Connection Traversal
Executes Relay cursor query posts(first: 50, after: $cursor) with topic hierarchy filters and thread recursion.
Endpoint: POST /v1/graphql
Stage 2 · Thread Enrichment
RFC Context Assembly
Correlates inline comments, author attributions, and discussion threads alongside post Markdown bodies.
Model: Post + Inline Comments
Stage 3 · Entity Extraction
Architecture Mapper
Maps design decisions, microservices, and runbooks into typed graph nodes via DOCUMENT_SOURCE_ATTR="slab".
Graph: (RFC)-[:DECIDES]->(Architecture)
Stage 4 · Agent Recall
Multi-Hop Graph RAG
AI coding copilots traverse historical decision paths to understand why infrastructure tradeoffs were made.
Recall: cognee.search(query, datasets)
⚡ Relay GraphQL Cursor ➔ In-Memory Comment Threading ➔ Cognify Architecture Extraction ➔ Graph Multi-Hop Query

Key Engineering Highlights

  • GraphQL Connection Pagination: Recursively traverses Slab's cursor-based pagination schema (posts(first: 50, after: $cursor)) to ingest arbitrarily large documentation vaults without memory bloat.
  • Inline Comment & Discussion Context: Ingests inline comments and author attributions alongside post content. If an engineer commented on an RFC explaining an edge-case caveat, the AI agent preserves that context.
  • Topic Scoping: Supports whole-organization sync or surgical scoping by specific Topic IDs (e.g. Infrastructure, Security, Platform).
import cognee
from cognee_community_connector_slab import slab_source

# Ingest engineering runbooks and architecture docs
source = slab_source(
    token="SLAB_API_KEY",
    topic_ids=["infra_topic_id", "security_topic_id"],
    include_comments=True
)

await cognee.add(source)
await cognee.cognify()

# Instant recall over team runbooks
answer = await cognee.search("What is our disaster recovery failover procedure for Kafka?")

Support Without Amnesia: The Freshdesk Connector

🔗 Dedicated Article Permalink: freshdesk.html →

Support engineers and AI customer service agents frequently encounter variations of the same complex customer issues. Without shared institutional memory, resolutions are repeatedly rediscovered from scratch.

The Freshdesk connector syncs resolved customer tickets, conversation threads, and internal solution articles directly into Cognee's semantic memory.

Systems Topology: Freshdesk Support to Triplet Graph Pipeline REST v2 · Multi-Turn Thread Normalizer
Stage 1 · Ingress & Backoff
Freshdesk REST v2
Pulls tickets, conversations, and solution articles. Handles HTTP 429 backoff using standard Retry-After parsing.
Endpoints: /tickets & /solutions
Stage 2 · Thread Resolution
Conversation Stager
Reconstructs chronological dialogue turns, differentiates Requester from Support Agent, preserves resolution steps.
Model: Structured Problem + Fix
Stage 3 · Cognify Processing
Root-Cause Extractor
Extracts root causes, affected components, and fix steps into typed relationships via DOCUMENT_SOURCE_ATTR="freshdesk".
Graph: (Bug)-[:RESOLVED_BY]->(Patch)
Stage 4 · Copilot Recall
Automated Triage RAG
Customer support bots match incoming bug reports against past resolved tickets with exact historical resolutions.
Query: cognee.search(error_log)
⚡ REST v2 Rate-Aware Polling ➔ Multi-Turn Chronological Normalization ➔ Root-Cause Triplet Cognify ➔ Fast Zero-Shot Resolution

Key Engineering Highlights

  • Unified Support Model: Concurrently syncs published solution articles (troubleshooting manuals, FAQs) and resolved customer tickets.
  • Multi-Turn Thread Reconstruction: Preserves conversational history between customers and agents, highlighting the exact resolution step that closed the ticket.
  • Robust Backoff & Rate Limit Handling: Inspects HTTP 429 status codes and respects Retry-After headers to ensure uninterrupted syncing on rate-limited tiers.
import cognee
from cognee_community_connector_freshdesk import freshdesk_source

source = freshdesk_source(
    api_key="FRESHDESK_API_KEY",
    domain="company.freshdesk.com",
    include_tickets=True,
    include_solutions=True,
    since_date="2026-09-01T00:00:00Z"
)

await cognee.add(source)
await cognee.cognify()

# Triage incoming tickets against historical resolutions
res = await cognee.search("How was the OAuth2 token refresh race condition resolved last month?")

Turning Spoken Words into Knowledge Graphs: The tl;dv Connector

🔗 Dedicated Article Permalink: tldv.html →

Remote engineering organizations spend hundreds of hours every month in Zoom and Google Meet calls discussing roadmap decisions, customer discovery feedback, and sprint retrospectives.

Once a meeting concludes, that context is effectively lost or locked inside hour-long video recordings. The cognee-community-connector-tldv extracts meeting recordings, speaker-attributed transcripts, and AI-generated summary notes, transforming ephemeral spoken dialogue into searchable semantic graph nodes.

Systems Topology: tl;dv Meeting Intelligence to Graph Pipeline REST v1 · Speaker Transcript Synthesis
Stage 1 · Multi-Resource Ingress
tl;dv API v1
Parallel fetching of meeting metadata (/meetings), speaker turns (/transcript), and AI notes (/notes).
Auth: x-api-key + Rate Backoff
Stage 2 · Dialogue Formatter
Speaker Turn Stager
Formats timestamped speaker turns ([04:12] Alice: ...), synthesizes executive notes, and extracts attendees.
Format: Speaker Dialogue AST
Stage 3 · Entity Extraction
Decision & Action Graph
Links action items to assignees and roadmap topics via DOCUMENT_SOURCE_ATTR="tldv" with replace disposition.
Graph: (Speaker)-[:COMMITS_TO]->(Task)
Stage 4 · Team Memory
Verbal Decision Recall
Autonomous agents query meeting decisions, stakeholder commitments, and sprint blockers instantly.
Query: cognee.search(meeting_query)
⚡ Parallel Multi-Resource Fetch ➔ Speaker Dialogue Parsing ➔ Action Item Triplet Extraction ➔ Verbal Enterprise Memory

Technical Architecture

  • Multi-Part Document Synthesis: Combines meeting metadata (organizer, date, duration), executive summaries, action item checklists, and timestamped speaker dialogue into structured Markdown.
  • Incremental Time-Window Sync: The connector accepts a since_date ISO timestamp, querying only recordings created or modified since the last pipeline run.
  • Speaker Attribution in Entity Graph: Transcripts tag individual speakers (e.g. [04:12] Alice:), allowing Cognee's entity extraction to correlate decisions with specific stakeholders.
import cognee
from cognee_community_connector_tldv import tldv_source

# Ingest recent sprint planning and customer discovery calls
source = tldv_source(
    api_key="TLDV_API_KEY",
    since_date="2026-10-01T00:00:00Z",
    include_transcripts=True,
    include_notes=True
)

await cognee.add(source)
await cognee.cognify()

# Ask your AI agent what happened in meetings
summary = await cognee.search("What action items were assigned to Bob during Monday's sprint planning?")
print(summary)

Under the Hood: Hunting Down the FalkorDB Visualization Bug

🔗 Dedicated Article Permalink: falkordb.html →

While contributing data connectors to Cognee Community, we discovered a critical bug in cognee-community-hybrid-adapter-falkor (Issue #262): every graph dataset containing edges crashed on visualization with KeyError: 'source_node_id'.

Systems Topology: FalkorDB Graph Extraction & UUID Resolution Pipeline Cypher Optimization · RFC Issue #262
Stage 1 · Cypher Traversal
Graph Pattern Match
Executes Cypher query MATCH (n)-[r]->(m) across all entities and typed relationships in FalkorDB graph memory.
Query: MATCH (n)-[r]->(m)
Stage 2 · Projection Binding
UUID Endpoint Projection
Directly projects node UUIDs n.id AS source, m.id AS target instead of internal integer FalkorDB IDs.
Return: n.id, m.id, TYPE(r), props
Stage 3 · Fail-Safe Adapter
Defensive Normalizer
Casts projected endpoint IDs to str() with graceful legacy edge property fallback; eliminates uncaught KeyError.
Safety: record[0] or props.get(...)
Stage 4 · Visualization
Knowledge Graph UI
Transmits valid 4-tuple edge models to Cognee's visual explorer with 100% endpoint integrity and zero crashes.
Status: 200 OK · D3 / Cytoscape
⚡ Cypher Graph Traversal ➔ Direct Node UUID Projection ➔ Defensive Null Fallback ➔ Interactive Visual Graph

Root Cause Analysis

In FalkorDB Cypher, edge insertions performed by add_edges() execute the following query: 

UNWIND $items AS e
MERGE (source {id: e.source_id})
MERGE (target {id: e.target_id})
MERGE (source)-[r:{rel_type}]->(target)
SET r += e.props, r.updated_at = timestamp()

Notice that e.props only contains custom user attributes and relationship_name. It never writes source_node_id or target_node_id to the edge property map.

However, FalkorDBAdapter.get_graph_data() queried: 

query = """
MATCH (n)-[r]->(m)
RETURN ID(n) AS source, ID(m) AS target, TYPE(r) AS type, properties(r) AS properties
"""
result = await self.query(query)
edges = [
    (
        record[3]["source_node_id"],  # <- CRASH: KeyError!
        record[3]["target_node_id"],  # <- CRASH: KeyError!
        record[2],
        record[3],
    )
    for record in result.result_set
]

Because properties(r) (index 3) never contained those keys, the list comprehension failed immediately. In addition, ID(n) returned FalkorDB's internal integer ID, which contradicted the string UUIDs stored in Cognee's node records!

The Fix

We refactored the Cypher projection to bind the endpoint nodes' business identifiers directly: 

query = """
MATCH (n)-[r]->(m)
RETURN n.id AS source, m.id AS target, TYPE(r) AS type, properties(r) AS properties
"""
result = await self.query(query)
edges = [
    (
        str(record[0]) if record[0] is not None else record[3].get("source_node_id", ""),
        str(record[1]) if record[1] is not None else record[3].get("target_node_id", ""),
        record[2],
        record[3],
    )
    for record in result.result_set
]
Verification & Conformance: We authored unit regression tests in packages/hybrid/falkordb/tests/unit/test_get_graph_data.py covering UUID resolution and legacy fallback. All unit tests and Ruff linter checks pass with zero errors.
