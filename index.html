Every time an AI agent receives a prompt, it starts with an empty context. While traditional retrieval-augmented generation (RAG) using vector search retrieves similar paragraphs, it struggles with structural entity relationships — who wrote which feature, how dependencies link, and when updates were published. Here is how I built the Webflow CMS data-source connector for Cognee during Mergetober, giving AI agents long-term, self-updating graph memory.

The Problem: The Fragility of Scraping

Webflow powers modern landing pages, technical documentation hubs, and company blogs. Historically, AI systems trying to digest Webflow content rely on web crawlers. This introduces serious flaws:

  • Noisy Markup: Navigation bars, tracking pixels, cookies, and footer links contaminate the LLM context window.
  • Unstable Content Hashes: Modifying a single CSS class causes scrapers to detect a brand-new page, bloating the vector store with duplicate nodes.
  • No Deletion Propagating: When a draft is unpublished or a blog post is removed, standard vector databases retain the outdated information indefinitely.

Engineering the Webflow Connector

The connector is packaged under packages/connector/webflow/ in the cognee-community repository, adhering to Cognee's modern document-mode ingestion pattern.

1. Opting Into Document Mode

Unlike tabular SQL sources where data rows map to relational columns, Webflow CMS entries are rich editorial documents. We declare document mode via:

pythoncognee_community_connector_webflow/webflow.py
from cognee.tasks.ingestion.dlt_utils import DOCUMENT_SOURCE_ATTR

source = _webflow()
# Opts into Cognee's document ingestion pipeline:
setattr(source, DOCUMENT_SOURCE_ATTR, "webflow")
return source

This informs Cognee's engine that rows should be routed through cognify (LLM entity and relationship discovery) rather than strict relational schemas.

2. Clean Markdown Formatting

Webflow CMS delivers rich text embedded in HTML. The connector uses an intelligent extraction pipeline that preserves headings, bullet lists, and code blocks while stripping layout noise. Title, canonical URL, and slug are kept stable to prevent content-hash churning:

pythonField Transformation
def _item_to_row(item: dict, collection_id: str) -> dict:
    field_data = item.get("fieldData") or {}
    item_id = item.get("id") or item.get("_id", "")
    title = field_data.get("name") or field_data.get("title") or f"Item {item_id}"
    slug = field_data.get("slug", "")

    return {
        "id": item_id,
        "url": f"webflow://collection/{collection_id}/item/{slug or item_id}",
        "title": str(title),
        "content": _render_fields_to_markdown(title, field_data),
    }

3. Automated Forget-on-Delete

Why replace disposition matters: Because Webflow's API has no separate deletion feed, the connector runs a full snapshot with write_disposition="replace". If an article is deleted or unpublished in Webflow, it is absent from the snapshot. Cognee's built-in orphan_cleanup detects the missing item and purges it from the graph and vector stores automatically.

How to Use It in 4 Lines of Code

Once installed via pip install cognee-community-connector-webflow, syncing your Webflow CMS into an AI agent's memory takes only four lines:

pythonsync_webflow.py
import asyncio
import os
import cognee
from cognee_community_connector_webflow import webflow_source

async def main():
    # 1. Initialize connector with site credentials
    source = webflow_source(
        token=os.environ.get("WEBFLOW_API_TOKEN"),
        site_id=os.environ.get("WEBFLOW_SITE_ID"),
    )

    # 2. Add source to Cognee staging
    await cognee.add(source)

    # 3. Cognify: extract knowledge graph & embeddings
    await cognee.cognify()

    # 4. Search and recall information
    results = await cognee.search("What announcements were made in our latest product release?")
    print(results)

if __name__ == "__main__":
    asyncio.run(main())
